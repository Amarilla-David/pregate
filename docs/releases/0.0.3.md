# Release 0.0.3

**Pregate** `v0.0.3`, core `0.0.1`. macOS ARM64 stays the stable platform. Linux and Windows archives stay experimental until native validation is recorded.

**If you use Windows and 0.0.2, upgrade.** Two bugs in 0.0.2 could let an edit through without a finding, even on a project you had agreed to protect. Install 0.0.3, then review the project update it prepares (`pregate update --project --preview`) and approve that exact digest. A global update prepares that review for each enabled project whose lock still pins an older engine.

## Windows fixes

- **An unaccepted preset made the hook skip the edit.** On Windows, `git add` rewrites the preset's timestamp, and the file clock can sit ahead of the hook. Pregate then behaved as if the project had no contract. The pre-edit hook exited successfully and recorded nothing, so the write was allowed. 0.0.3 denies that call and tells you to commit the preset and start a new session. The edit does not land in silence.
- **A short path and a long path looked like two projects.** Windows sometimes spells a folder with an 8.3 short name (`C:\Users\ME~1\...`) and sometimes with the long name. Consent saved under one spelling did not match the other, so a project you had consented to looked unconsented and the hook exited without a finding. 0.0.3 treats those two spellings as the same directory. It compares the file's identity, not the letters in the path.

## Also in this release

- When Git cannot be used, the edit is still denied, and the message names the failure: Git is missing, the directory is not a repository, or Git returned some other error. Each message says what to do next.
- Release archives carry the GNU Library General Public License, version 2, for the JavaScriptCore that Bun 1.4.4 links, and the GNU Lesser General Public License, version 2.1, for tinycc. The notice links to the pinned Bun, WebKit, and tinycc source and describes how to rebuild.
- Codex 0.166.0 is the verified CLI. For Bash, the hook's working directory is the command's resolved directory. A command that runs in a subfolder still uses the same project. A working directory outside the repository does not drop that project's gate.
- A shell, interpreter, or `make` command whose script is not a literal path is denied inside an enabled project. The denial says how to name the script literally.
- An unexpected error on the trust path is no longer swallowed. The hook denies it. A catch that still handles every error says why that fallback is fail-closed.
- Pack precision is recorded for maintainer-labeled packs. Packs with no labels stay unmeasured. CI also gates compiled Pre-hook latency on Linux, macOS, and Windows.

The previous public tag is [0.0.2](https://github.com/pedroknigge/pregate/releases/tag/v0.0.2). The first public tag is [0.0.1](0.0.1.md).

## Install

These commands apply once `v0.0.3` is published. Install a tag that has actually been published, and check the archive against `SHA256SUMS` before you run it. There is no npm package.

macOS and Linux:

```sh
gh release download v0.0.3 --repo pedroknigge/pregate --pattern install.sh --pattern SHA256SUMS
sh install.sh --version 0.0.3
```

Windows PowerShell:

```powershell
$dir = Join-Path $env:TEMP pregate-install
New-Item -ItemType Directory -Force -Path $dir | Out-Null
gh release download v0.0.3 --repo pedroknigge/pregate --pattern install.ps1 --pattern SHA256SUMS --dir $dir
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$dir/install.ps1" -Version 0.0.3
```

The Windows check for this tag is [windows verification](../guides/windows-verification.md). The commit to verify is the v0.0.3 tag.
